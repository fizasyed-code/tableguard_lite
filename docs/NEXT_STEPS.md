# Next integration gate

1. Confirm exact machine: CPU model, system RAM, available NVIDIA VRAM (if any), and actual Intel Core Ultra Series 2/3 access.
2. Obtain and inspect the full online brief and approved task assets. Record the exact online cutoff and timezone.
3. M2 proves a working baseline using the approved scene, actual camera observations and task-compatible policy. Document action size/order/units and coordinated reset/cancel/hold semantics.
4. M3 implements the real visual monitor on observations from that scene. The starter's fixture labels are not a model and must not be wired into the actual controller.
5. M1/M2 connect `decide` to a supported action boundary and exactly one real corrective action. Protected goals must be checked after/during repair; declaring them protected does not guarantee preservation.
6. M5 runs independent matched evaluation with no privileged state/labels reaching the runtime. Preserve failure and timeout records.

The first public sample is for I/O/video inspection. It is not evidence that any pretrained controller can perform the official task.
